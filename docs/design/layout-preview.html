01

现状：只看宽度，横屏被误判

当前判定是 innerWidth < 1024 && !鼠标设备。 手机横屏 792 仍小于 1024，于是套上了为竖屏设计的手机 UI —— 而这套 UI 的 header 与 composer 都是按「垂直空间充裕」的前提定高的，横屏后它们不吃这一套。

02

手机横屏 792×360：三个候选方案

这是问题最集中的场景。三个方案都在这一个尺寸下画，方便直接比。

03

平板：真正要解决的是「太宽」不是「太矮」

手机横屏的问题是高度不够；平板竖屏的问题反过来——高度充足，但内容单列铺满 800px 宽， 一行字横跨整个屏幕，阅读体验反而比手机差。这两个场景的正确解法不同。

我的判断

  1. 手机竖屏（360×792）保持现状 —— 这套 UI 就是为它设计的，内容占 69%，没必要动。
  2. 手机横屏（792×360）走方案 B —— 只退回官方不够（官方 composer 高度未验证）， 真正的解法是把 header 压成单行、composer 去掉 stats、吃掉手势条。内容 109 → 269。
  3. 平板（宽度 ≥ 768 且非手机）走官方布局 —— 平板的痛点是「太宽」不是「太矮」， 退回官方让侧栏折叠成图标条，正文宽度自然收窄，比任何手机 UI 变体都合适。
  4. 判定用宽高比，不用宽度 —— 手机竖屏 0.45、手机横屏 2.20、平板竖屏 0.63、平板横屏 1.60。 以 1.0 为界分「竖」与「横」就够，再配合宽度兜底。

注：方案 A / B 里的 header 与 composer 高度是按目标设计的取值，不是实测值。 方案 B 的 269px 内容高度需要真机验证后才能确认；官方布局在 360px 高下是否更优也待实测。
